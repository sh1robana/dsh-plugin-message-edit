# DSH 插件升级适配

将当前插件适配到明确的 DSH 目标版本，交付可复用的源码、验证证据和准确的兼容结论。回复、文档、注释使用简体中文。

## 先确定项目、版本与任务边界

- 在插件仓库操作，先读适用的 `AGENTS.md`、`CLAUDE.md`、README、当前进度和最近日志，再读 `package.json`、manifest、相关实现与测试。执行 `git status --short --branch`，保留已有修改。
- 区分三个值：项目最后实际验证的宿主版本、开发依赖声明的版本、本次目标宿主版本。不能从依赖版本推断已完成桌面验证。
- 用户指定版本时使用该版本；说“当前安装的新版本”时只读确认桌面安装版本及其捆绑运行时；说“最新版本”时查询官方发布记录，记录确切版本、发布渠道和来源。不要把全局 CLI、桌面宿主和 npm 包的版本混为一谈，也不要自动升级 DSH。目标无法确定时只询问版本或安装位置，继续独立的项目调查。
- “评估、检查兼容性”保持只读；“更新适配”允许修改本仓库源码、依赖、测试、构建产物和维护文档。安装到桌面 profile、重启宿主、发送模型请求、提交推送及公开发布，按本次实际授权执行，不从 Skill 本身推导权限。

## 从目标版本取证，再决定改什么

以目标版本的实际接口为准，按需使用以下证据：

1. 目标宿主的运行检查、已安装包的 `package.json`、README、类型声明、实际导出和构建代码。
2. 对应发行标签或提交的官方源码、发布说明及受影响包的文档。
3. 官方 `cordis-plugin-development` Skill 的相关章节，作为接口发现与开发方法参考。

官方入口：[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)、[发布记录](https://github.com/deepseek-ai/deepseek-harness/releases)、[官方 Skill](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset/skills/cordis-plugin-development/SKILL.md)。`master` 仅用于导航；使用其中的具体 API 前，确认它也存在于目标版本。按需查找目标版本对应路径，不要求旧版目录结构保持不变。

如果执行环境提供 `cordis_inspect_list` / `cordis_inspect_query`，用它们检查实际宿主；Codex 没有这些工具时，读取目标安装包、类型或对应源码即可，不把安装另一套工具当作适配前置条件。官方 Skill 不可加载时继续取证，不依赖它才能工作。

沿插件实际 imports、服务调用、事件、客户端注册及构建配置追踪宿主耦合点。先列简短影响清单：接口、目标版本证据、受影响入口、需改动或无需改动、验证方法。发布说明没有提及变化不等于接口没变；只有旧版依赖或手写 mock 的测试通过，也不能证明新版可用。

## 完成最小适配

- 只修有证据影响当前插件的部分；新版本不需要逻辑修改时，继续验证，不强行重构或发版。
- 依据目标宿主实际包版本调整开发依赖和锁文件，不能假定所有 `@deepseek-ai/*` 包与桌面版本同号。保持运行时宿主依赖在 `peerDependencies` 的现有约定；检查 `engines.dsh`、客户端 `inject`、exports 和 bundle manifest 是否需要同步调整。
- 版本范围只表达已有证据支持的范围。默认保留已支持版本的使用方式；若目标 API 与旧版冲突，先判断能否用小范围能力检测兼容。必须放弃旧版、迁移持久化数据或改变核心行为时，说明影响并取得决定后再实施，不暗中缩小支持范围。
- 保存既有数据意义、事件兼容和功能语义。协议变化沿宿主解析、传输、客户端解码、持久化和投影一起检查；修复缺陷时补充对应行为测试。
- 修改源码与构建配置，通过项目构建生成产物，不直接修补生成文件。优先复用现有脚本，不另建升级框架。

## 验证与兼容结论

复用仓库规定的构建、测试和验收入口。若当前项目是 `@sh1robana/dsh-plugin-message-edit`，读取 [消息编辑插件适配入口](references/message-edit.md)；其他插件按其项目规则验证，不照搬消息编辑脚本。

验证分开记录：

- **源码与自动化**：确认构建使用目标包的类型和实际导出，执行项目构建与行为测试。
- **安装与加载**：获准安装后核对桌面 profile 中的插件文件、实际加载构建和宿主错误。
- **真实行为与界面**：在目标版本的独立测试会话操作，核对项目规定的关键路径、状态和实际渲染。涉及请求模型的测试须有授权，不能拿真实用户对话试验。

缺少目标宿主、安装授权、浏览器操作能力或人工验收结果时，完成不受影响的工作，列出缺失检查、所需环境及由 AI 或维护者继续的具体动作。已按目标接口完成修改且构建测试通过时，才标记“源码适配完成，目标桌面待验收”；目标接口资料不足时，记录具体未解决点，不能提前声称源码适配完成。安装成功、静态测试通过或旧日志不能替代目标版本桌面验收；有实测失败时，修复后验证再下结论。

## 交付与继续

- 交付写清插件版本、基线与目标 DSH 版本、修改或无需修改的理由、自动化/安装/桌面验证结果，以及剩余问题的下一步。
- 实施任务按项目约定更新日期日志与进度；只读评估直接回复结论，不落盘。仅在目标版本验收完成后，更新“已验证兼容版本”；保留仍有效的历史兼容记录。适配过程中修改依赖或 manifest 的目标声明时，另记待验收状态，不能写成已验证。
- 只有实际需要发版且已有发布授权时，按项目发布指南同步版本、CHANGELOG 和安装说明。不覆盖已发布安装包。
- 后续收到安装许可、目标环境或人工验收反馈时，接续已有成果完成缺失环节，不从头重复有效检查。
