# 开发与发布

项目仓库：[sh1robana/dsh-plugin-message-edit](https://github.com/sh1robana/dsh-plugin-message-edit)。本页以 `0.3.2` 为发行示例，首个正式版本为 `0.3.0`。上线状态以各渠道的实际条目为准。

本次发行版本为 `0.3.2`，包含 DSH `0.2.1-rc.2` 适配及日志结构修复，已获准发布到 GitHub 和 npm；两渠道结果分别在 `log/README.md` 记录。既有 `0.3.1` 发行包不覆盖，社区目录更新另按授权执行。

## 构建安装包

需要 Node.js 24 或以上。先创建 `artifacts` 目录，安装开发依赖后执行：

```sh
npm ci
npm run build
npm test
npm pack --ignore-scripts --pack-destination artifacts
```

`npm pack` 实际生成 `artifacts/sh1robana-dsh-plugin-message-edit-0.3.2.tgz`。为统一 GitHub Release 附件名称，在 PowerShell 中复制为发行文件名：

```powershell
Copy-Item -LiteralPath ./artifacts/sh1robana-dsh-plugin-message-edit-0.3.2.tgz -Destination ./artifacts/dsh-plugin-message-edit-0.3.2.tgz
```

GitHub Release 上传使用复制后的 `artifacts/dsh-plugin-message-edit-0.3.2.tgz`，两份文件内容相同。安装包包含已构建的宿主与客户端、README、许可、构建指纹及演示截图，不包含本机配置、会话或备份。更新版本时，以上两个文件名中的版本号一并调整；已发布安装包不覆盖。

当前工作区的官方宿主开发依赖对齐 DSH `0.2.1-rc.2`、Cordis `4.0.5`，运行时依赖保留在 `peerDependencies`。顶层 `engines.dsh` 与相关 peer 使用 `0.2.0-rc.2 || 0.2.1-rc.1 || 0.2.1-rc.2`；实际完成桌面验证的仍为前两个版本，`0.2.1-rc.2` 待桌面验收。改名、改版本或改源码后都需要重新构建、测试和打包。

`npm test` 默认执行 109 项检查。将 `DSH_TARGET_ATTACHMENT_CLIENT` 设置为目标宿主 `dsh-client-ui-attachment/lib/client.js` 的绝对路径，额外检查原生拖放；将 `DSH_TARGET_MODULES_CLIENT` 设置为目标 `dsh-client-modules/lib/client.js` 的绝对路径，额外检查真实模块加载器与本次客户端产物。两个输入均启用时共 111 项，只读取目标实现，不安装或重启宿主。真实 AgentLoop 回归还使用官方完整 V4 恢复校验器，覆盖首回合助手编辑后继续对话的日志结构；该校验器仅为开发依赖，不添加为运行时 peer。桌面行为由维护者在独立测试会话验收，分别记录在 `log/`。

本机已将两个目标检查输入单独保存在 `.inspection/host-inputs/0.2.1-rc.2/`，使用方式见该目录的 `README.md`，无需保留整套宿主解包副本。这些是本地可选输入，不属于源码或发行包；干净克隆按上面的目标文件路径提供，适配新版时重新从对应目标取证。

## GitHub

1. 核对 Git 远程地址和目标分支，确认推送到本项目仓库；本工作区的 `origin` 是 Moeblack 上游，不能直接作为发布目标。
2. 核对 `package.json` 的 `repository`、`homepage`、`bugs` 和贡献者指向实际项目与 GitHub 公开名称。
3. 推送源码，保留上游来源与许可。不要推送 `.inspection`、`.local-backups`、`.dsh`、`node_modules` 或个人会话截图。
4. 创建 `v0.3.2` Release，附上测试通过的 `dsh-plugin-message-edit-0.3.2.tgz`，核对下载内容。安装时将 Release 附件的完整链接交给 `dsh plugin add`。

GitHub CLI 可以通过 `gh auth login --hostname github.com --git-protocol https --web` 登录。账号认证由维护者本人完成。

## npm

仅在获得 npm 发布授权后执行本节；GitHub Release 发布不会自动更新 npm。

`dsh-plugin-message-edit` 的无作用域包名已被其他维护者占用。npm 包使用维护者的作用域 `@sh1robana/dsh-plugin-message-edit`；GitHub 仓库名称不受影响。

使用实际维护者的 npm 账号完成官方网页登录：

```sh
npm login --auth-type=web --registry https://registry.npmjs.org/
npm whoami
```

包名已经同步到 manifest、锁文件、补丁、构建配置和 README。重新构建、测试、打包后，使用检查过的安装包执行 `npm publish ./artifacts/dsh-plugin-message-edit-0.3.2.tgz --access public --tag latest`。

网页登录或发布的双重验证由账号持有人完成，不需要向协作者提供密码或长期令牌。发布后核对 `npm view @sh1robana/dsh-plugin-message-edit@0.3.2 version dist.integrity repository`，再用干净的测试 profile 验证从 registry 拉取。

参考：[npm 作用域公共包发布说明](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages/)、[发布双重验证](https://docs.npmjs.com/requiring-2fa-for-package-publishing-and-settings-modification/)。

## DSH 社区市场

[dsh-market](https://github.com/dsh-market/dsh-market) 使用 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 的社区目录。按照其[贡献指南](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md)投稿：

1. 仓库需真实可用、声明 `dsh.bundle`，且**创建满一天**。
2. 在目录仓库新增 `data/plugins/sh1robana__dsh-plugin-message-edit.yml`，分类使用 `session`。
3. 填写实际仓库地址、英文与中文功能描述，`tarball` 指向 GitHub Release 的 HTTPS `.tgz` 下载链接。本仓库的 `docs/market-entry.yml` 是投稿条目。
4. 提交目录 PR，维护者审核合并后市场再同步；提交成功不等于已经上架。

npm 发布不是市场收录的必要条件。带版本号的安装包使用固定 tag 下载链接；使用 `latest/download` 时应提供文件名固定的安装包。仓库的 `screenshots.json` 声明两张无私人资料的示例截图。

本项目基于原插件继续维护，并增加原地保存、完整附件编辑和编辑输入框等功能；投稿介绍实际差异，避免宣称没有同类插件。

## 本地更新与验证

源码目录提供 `scripts/install-desktop.ps1`，会先备份配置再调用桌面 CLI；配置备份只保存在本地。迁移旧版时先卸载 `dsh-message-edit`，再安装本项目，避免两个实现重复注册。

安装后彻底退出并重启 DSH。`npm run check:installed` 可检查安装版本和产物哈希；桌面页面的 `__DSH_MESSAGE_EDIT__.diagnostics()` 可核对实际加载的前后端构建。
